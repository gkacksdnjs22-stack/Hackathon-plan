# 길 — 마음이 향하는 국내 여행

처음 가는 지역의 관광지·식당을 찾아보고 이동 예상시간을 참고해, 사용자가 여행 계획서를 완성하는 웹앱입니다. TourAPI의 가까운 관광지로 추천 초안을 제공하고, 날짜별 출발지·교통편과 필요한 일정·시간·메모를 직접 정할 수 있습니다.

## 실행

Node.js 24 이상과 Git이 필요합니다. 로컬 DB는 Node 내장 SQLite를 사용합니다. 아래 명령은 PowerShell 기준입니다.

### 1. 저장소와 실행 폴더 준비

처음 받는 경우, 저장소를 보관할 폴더에서 실행합니다.

```powershell
git clone https://github.com/gkacksdnjs22-stack/Hackathon-plan.git
cd Hackathon-plan
cd 'GitHub-업로드용'
node --version
```

이미 저장소를 받은 경우에는 저장소 루트에서 `cd 'GitHub-업로드용'`으로 이동하면 됩니다. `package.json`과 `server.mjs`가 있는 폴더가 실행 폴더입니다. `node --version`이 `v24` 이상인지 확인하세요.

### 2. 로컬 API 키 설정

실행 폴더에 `.env` 파일을 만들고, 아래 예시의 값을 본인에게 발급된 공공데이터포털 인증키로 바꿔 저장합니다. 파일 이름이 `.env.txt`가 되지 않도록 확인하세요.

```dotenv
DATA_GO_KR_SERVICE_KEY=공공데이터포털_인증키
```

`DATA_GO_KR_SERVICE_KEY`는 관광지·음식점 조회와 TAGO 서비스가 공유합니다. 공통 키를 쓰더라도 사용할 API의 활용신청은 각각 승인되어 있어야 합니다. 공공데이터포털의 디코딩 키와 인코딩 키를 모두 지원하며, 이전 `TOURAPI_SERVICE_KEY`·`TAGO_SERVICE_KEY` 설정도 호환합니다. 음식점도 기존 TourAPI로 조회하므로 별도 맛집 키는 필요하지 않습니다. 키를 바꿨으면 서버를 다시 시작합니다.

차량·대중교통 경로 조회도 사용할 경우, 같은 `.env`에 `KAKAO_REST_API_KEY=카카오_REST_API_키`를 추가합니다. 자세한 설정과 제공 범위는 아래 **출발지와 교통편 시간표**를 참고하세요. 이 키가 없으면 해당 경로 조회 기능을 사용할 수 없습니다.

`.env`는 Git 추적에서 제외됩니다. 실제 키를 README나 소스 코드, PR에 적지 마세요. 로컬 계정 DB와 인증용 비밀값은 서버가 처음 실행될 때 자동으로 준비합니다.

### 3. 서버 실행과 접속

```powershell
npm start
```

로컬 실행에는 별도의 `npm install`이 필요하지 않습니다. 배포 파일을 빌드할 때는 아래 Cloudflare 안내에 따라 `npm ci`로 개발 도구를 설치합니다.

터미널에 `길: http://127.0.0.1:3000`이 표시되면 브라우저에서 해당 주소를 엽니다. 서버를 사용하는 동안 터미널을 열어 두고, 종료할 때는 `Ctrl+C`를 누릅니다. `index.html`을 파일로 직접 열면 API 연동이 동작하지 않습니다.

- PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm.cmd start`를 사용합니다.
- `package.json`을 찾지 못하면 현재 위치가 `GitHub-업로드용` 폴더인지 확인합니다.
- 포트 사용 오류가 나면 기존 서버를 종료하거나 `.env`에 `PORT=3001`을 추가하고 다시 실행한 뒤, 터미널에 표시된 주소로 접속합니다.

앱 사용 중 궁금한 점은 **[이용 안내와 자주 묻는 질문](help.html#faq)**에서 확인할 수 있습니다.

## 일정 만들기와 편집

- 로그인·회원가입의 비밀번호와 비밀번호 확인 칸에서 **보기 / 숨기기**를 각각 전환할 수 있습니다. 창을 다시 열면 숨김 상태로 시작합니다.
- 관광지와 음식점 조회 목록에서 **주소 복사**를 지원합니다. 브라우저에서 복사를 허용하지 않으면 표시된 주소를 직접 선택해 복사할 수 있습니다.
- 일정 수정·추가와 식당 직접 입력의 메모 칸에는 현재 입력량과 최대 500자를 표시합니다.
- 노트의 여행 요약에 여행지 현지 날짜 기준 **D-day·오늘 출발·여행 중·지난 여행**을 표시합니다.
- 노트는 **하루 일정만 한 페이지에 표시**합니다. 위·아래의 **Day 01, Day 02… 책갈피**로 날짜를 전환하며 현재 페이지를 강조합니다. 전환하면 일정 위쪽으로 즉시 이동하고, 접힌 일정은 펼칩니다. 날짜 제목 옆에는 작은 Day 번호를 표시합니다. 날짜별 주소(`#/note/day/2`)와 브라우저 뒤로·앞으로 이동을 지원합니다. 페이지 전환만으로 편집 중인 메모나 일정 데이터가 바뀌지 않으며, 편집·되돌리기·다시 실행 중에도 선택한 페이지를 유지합니다. 새 노트 생성과 다른 노트 불러오기 시에는 첫날부터 표시합니다.
- 날짜별 **일정 접기 / 펼치기**와 관광지 수·체류시간·입력된 이동시간 요약을 제공합니다. 미정 구간은 별도로 표시하며 식사·휴식·마무리 시간은 이동 합계에 포함하지 않습니다. 다른 페이지의 일정과 접어둔 일정도 인쇄·PDF에는 모두 표시합니다.
- 저장한 계획은 **최근 수정순 / 여행 시작일 빠른순**으로 정렬할 수 있습니다. 정렬은 목록의 표시 순서만 바꿉니다.
- **저장한 계획 검색**에서 계획 이름과 여행 지역을 검색합니다. 띄어 쓴 단어를 모두 포함하는 계획을 보여주며 영문 대소문자는 구분하지 않습니다. 검색 중에도 정렬·불러오기·삭제를 이용할 수 있고, 목록 새로고침 후에도 검색어를 유지합니다. 계정이 바뀌면 검색어를 비웁니다.
- 노트의 **미정 이동 모아보기**에서 전체 날짜의 미정 구간을 확인합니다. 출발지·도착지·이동시간이 미정인 구간을 누르면 해당 날짜를 펼치고 입력 위치로 이동합니다. 시간을 저장하면 목록을 다시 계산하며, 조회만 한 예상시간은 입력 완료로 처리하지 않습니다.

아이디·비밀번호만으로 가입·로그인하고, **계획표 저장**으로 여러 계획에 이름을 붙여 계정에 보관할 수 있습니다. 시작 화면의 **저장한 계획**에서 불러오기·삭제를, 노트에서 변경사항 저장·새 계획으로 저장을 지원합니다. 다른 기기에서는 같은 계정으로 로그인한 뒤 저장 목록에서 계획을 엽니다. 서로 다른 기기의 수정이 겹치면 덮어쓰지 않고 최신 계획 불러오기 또는 새 계획 저장을 안내합니다.

브라우저 임시 저장과 계정 DB 저장은 별개입니다. 임시 저장본은 계정별로 구분하고, 로그아웃하면 해당 계정의 노트는 화면에서 숨깁니다. 다른 계정으로 로그인하면 그 계정의 계획만 조회·수정·삭제할 수 있습니다. 계정 DB 저장은 저장 버튼을 눌렀을 때 실행합니다. 이메일 확인·소셜 로그인·비밀번호 재설정은 제공하지 않으므로 아이디와 비밀번호를 기억해 주세요.

로컬 서버를 처음 실행하면 비공개 `.local/gil.sqlite`와 `.local/AUTH_SECRET.txt`를 생성합니다. DB와 비밀값 파일은 삭제하거나 공유하지 마세요. Cloudflare에는 별도의 D1 DB를 만들고 `DB` 바인딩과 `AUTH_SECRET` Secret을 등록해야 합니다. 로컬 계정·계획은 배포 ZIP에 포함되지 않습니다.

- **여행의 시작**과 **나만의 여행 노트**를 별도 화면으로 나눴습니다. 시작 화면에서 ‘추천으로 시작하기’를 누르면 추천 초안이 있는 노트 화면으로 이동합니다. 노트 상단의 ‘길’을 누르면 시작 화면으로 돌아가며, ‘여행 노트 보기’로 기존 노트를 다시 열 수 있습니다.
- 화면 주소는 `#/start`와 `#/note`입니다. 뒤로·앞으로 가기를 지원하고 노트 주소를 새로고침하면 저장본을 복원합니다. 저장본이 없으면 시작 화면을 안내합니다. 시작 화면의 조건을 바꾸거나 새 일정 생성이 실패해도 기존 노트는 유지하며, 새 일정 생성이 성공했을 때 교체합니다.
- 여행지·시작일·기간을 선택해 날짜별 일정을 생성합니다. **새 여행 시작일은 오늘부터 선택**할 수 있으며 지난 날짜는 달력과 키보드 이동에서 비활성화합니다. 현재 날짜를 매번 다시 계산하고, 자정을 넘겨 조회가 끝나도 지난 날짜로 새 노트를 만들지 않습니다. 기존 과거 여행 노트의 불러오기·편집은 유지합니다. 기간은 해당 지역에서 구성할 수 있는 권역 수에 따라 1~7일 중 가능한 값만 표시합니다.
- 여행지 목록과 관광지·문화시설의 이름·주소·좌표·유형은 TourAPI에서 불러옵니다. 추천 초안은 대표 장소 반경2.5km 안에 장소가3곳 이상인 권역을 사용합니다. 행정구역이나 실제 도로 경로를 기준으로 묶은 결과는 아닙니다. **장소 추가·교체 목록은 이 묶음 밖의 유효한 API 관광지까지 포함**합니다. 세종은 추천3곳과 전체 후보19곳을 구분합니다.
- 날짜별 방문 권역을 변경·교환하거나 전체 지역의 다른 관광지로 교체할 수 있습니다. 다른 권역의 장소로 교체하면 기존 추천 장소는 복구 가능한 제외 목록에 남고 새 장소를 추가합니다. 중복 방문을 확인하고 시간을 다시 계산합니다.
- 방문 권역 목록 위의 검색창에서 지역명이나 권역에 속한 관광지 이름으로 목록을 좁힐 수 있습니다. 검색과 선택만으로 일정이 바뀌지는 않으며 ‘변경 적용’을 누르면 반영합니다.
- 관광지는 체류시간과 메모를, 자유 시간·식사·이동·휴식은 이름·소요시간·메모를 수정할 수 있습니다. 수정한 시간에 맞춰 뒤 일정도 이동합니다.
- 시간 옆 **타임라인 점에 마우스를 올리면 ↑·↓ 버튼**이 나타나 관광지와 식사·휴식·이동의 순서를 바꿀 수 있습니다. 모바일은 점을 눌러 열고, 키보드는 Tab으로 점에 접근합니다. Escape나 바깥 클릭으로 닫습니다. **빼기**로 원하지 않는 추천 항목을 제외하고 날짜 아래 **뺀 일정 다시 담기**에서 복구합니다. 다른 교체 후보가 없는 지역도 순서 변경과 제외를 지원합니다. 출발·교통편 도착·도착 후 첫 이동·마무리는 시간 연결을 위해 유지합니다.
- 날짜 아래 작은 **일정 추가** 버튼에서 관광지·식사·휴식·이동 또는 직접 입력한 개인 일정을 작성합니다. 새 항목은 항상 **여행 마무리 바로 앞에 추가**하며 점의 순서 버튼으로 옮길 수 있습니다. 관광지는 현재 지역 전체 API 후보를 검색하며, 이미 담은 관광지는 중복으로 넣지 않습니다. 추천에서 뺀 관광지는 복구 목록에서 다시 담습니다. 추가 항목은 날짜별 최대20개이며 이름·시간·메모를 수정하거나 삭제할 수 있습니다. 추가 관광지도 다른 미사용 후보로 교체할 수 있습니다.
- 장소 순서가 바뀌면 해당 날짜의 관광 이동시간을 초기화하므로 다시 확인합니다. 선택한 지역 간 교통편과 다른 날짜는 유지합니다. 관광지를 추가했을 때 필요한 이동 구간도 직접 추가하며, 이동시간 0분은 미정으로 표시합니다.
- 출발 시각은 시·분 선택창의 **선택 완료**를 누르면 즉시 반영·저장됩니다. 별도의 ‘시간 적용’ 버튼은 없습니다.
- 마지막 ‘오늘 여행 마무리’는 숙소로 돌아가기·귀가 등으로 이름을 바꾸고 이동시간을 더할 수 있습니다. 이동이 없으면 0시간 0분으로 둡니다.
- 인쇄·PDF 버튼은 브라우저 인쇄 창을 엽니다.
- **여행 준비물**에서 항목을 추가·완료 체크·삭제합니다(노트당 100개, 이름 120자). **관광지 즐겨찾기**는 일정의 별 버튼이나 이름·주소 검색으로 최대 100곳을 모아두고 현재 보고 있는 날짜에 담을 수 있습니다. 이미 사용한 장소는 중복으로 추가하지 않으며, 뺀 추천 장소는 원래 날짜의 복구 목록에서 다시 담습니다. 관광정보에서 사라진 즐겨찾기는 목록에서 해제할 수 있습니다.
- 각 일정의 **색상 태그**에서 ‘꼭 가기·예약 완료·여유롭게’를 선택하거나 지웁니다. 색과 글자를 함께 표시하며 장소를 교체하면 해당 장소의 태그를 초기화합니다. 추가 일정을 삭제하면 그 태그도 삭제되고, 기본 일정을 잠시 빼 두면 복구 시 태그도 되살아납니다.
- 준비물·즐겨찾기·태그는 **여행 노트별로** 브라우저에 자동저장되며 계정의 ‘계획표 저장’에도 포함됩니다. 기존 노트도 바로 사용할 수 있고 되돌리기·다시 실행을 지원합니다. 준비물과 태그 변경은 편집 중인 일정 메모를 닫지 않습니다. 인쇄·PDF에는 준비물과 태그를 포함하고 검색·조작 버튼은 숨깁니다. 텍스트·캘린더 내보내기는 일정 본문만 포함합니다.
- **일정 내보내기**에서 현재 날짜 또는 전체 여행을 선택해 텍스트를 복사하거나 캘린더 `.ics` 파일을 내려받을 수 있습니다. 주소·저장한 메모·추가한 일정이 포함되며 빼 둔 일정은 제외됩니다. 편집 중인 내용은 먼저 저장하세요. 복사가 차단되면 텍스트 상자에서 직접 복사할 수 있습니다.
- 캘린더 파일은 한국 시간과 자정 이후 시각을 반영합니다. 이동시간 미정인 날짜는 임시 시각·잠정 일정으로 표시하고 미정 구간에 가짜 소요시간을 넣지 않습니다. 캘린더 앱의 가져오기를 이용하며, 이후 앱에서 수정한 내용과 자동 동기화되지 않습니다. 파일을 여러 번 가져오면 앱에 따라 중복될 수 있으니 기존 가져온 일정을 확인하세요.

작은 모바일 화면에서는 시간 표시를 카드 위에 배치해 입력 공간을 확보합니다. 달력·시간·권역 선택창은 보이는 화면 안에서 위치와 높이를 조정하며, 키보드나 주소창으로 화면 크기가 바뀌어도 열린 선택창을 유지합니다. 출처 안내와 이용 안내는 하단에서 나란히 표시합니다. 상단의 일반·성공 안내는 5초 뒤 사라지고 입력·선택·버튼 조작 시 바로 숨깁니다. 처리 중 안내는 완료까지, 오류 안내는 입력을 수정할 때까지 유지합니다.

기본 출발 시각은 09:00이며 18시 종료 제한은 없습니다. 자정을 넘으면 다음 날로 표시합니다. 기본 체류시간은 앱의 예상값이며, 권역 안 이동시간은 입력하거나 경로 조회 결과를 적용하기 전까지 0분(미정)입니다. 미정인 이동 구간이 있으면 전체 시각을 임시 계획으로 표시하며, 이동수단·장소 변경 시 관련 시간을 다시 입력합니다. 0분은 실제 이동이 없다는 확인이 아닙니다. 식사 이름은 배치 시각에 맞춰 표시하며 15~17시는 오후 식사로 안내합니다. 직접 수정한 식사 이름은 유지합니다.

## 출발지와 교통편 시간표

이동수단과 출발지·도착지는 날짜마다 선택합니다. 기차·시외/고속버스·비행기·배는 TAGO의 공식 역·터미널·공항·항구 목록에서 검색합니다. 버스는 고속버스와 시외버스를 구분하며 출발지와 도착지가 같은 서비스여야 시간표를 조회할 수 있습니다.

출발지와 도착지를 정한 뒤 ‘예상시간’을 펼치면 해당 날짜의 운행 시간표를 불러옵니다. TAGO의 **열차·고속버스·시외버스·국내항공·국내여객선 5개 서비스**를 연결했습니다. 교통편을 선택하면 출발·도착 시각과 소요시간을 반영하고, 뒤의 관광 일정을 함께 조정합니다. 선택한 교통편은 날짜별 `dayTransports`에 저장해 새로고침 후 복원합니다.

시외버스 API는 **한국시간 기준 당일 시간표만 조회**할 수 있습니다. 다른 날짜나 운행편이 없는 구간은 제공되는 결과를 안내하며 임의의 교통편을 만들지 않습니다. 시간표는 예정된 운행 시각이며 지연·결항 등을 반영한 실시간 도착 예측이나 예약 서비스가 아닙니다.

중간역·터미널에서 갈아탈 때는 **환승편 조회**에서 환승 장소와 실제 교통편 두 개를 선택하고 **환승 일정 적용**을 누릅니다. 예를 들어 조치원→대전, 대전→포항을 연결하면 첫 출발부터 최종 도착까지의 시간에 환승 대기도 포함합니다. 최소 환승 여유는 기본15분이며0~180분으로 바꿀 수 있습니다. 첫 편의 실제 도착 이후에 탈 수 있는 두 번째 편만 적용하며, 자정을 넘으면 도착 날짜와 다음 편의 출발일을 함께 확인합니다. 한 번의 환승을 지원하고, 같은 TAGO 서비스의 공식 장소끼리 연결합니다. 환승 장소를 자동으로 찾거나 기차와 버스 등 서로 다른 서비스를 연결하지는 않습니다.

시내·마을버스와 지하철은 장소·주소 검색 후 **대중교통 예상시간**을 펼치면 카카오맵에서 실제 경로의 시간·거리·환승 횟수를 조회합니다. 출발지→첫 관광지와 관광지 사이 구간에 사용할 수 있습니다. 해당 수단을 포함한 혼합 경로도 구분해 표시하며, 빠른 경로 최대5개 중에서 선택하고 **이용 노선 간단히 보기**로 노선·정류장 요약을 확인합니다. 도보만 선택한 구간은 직접 시간을 입력합니다. 장소·주소 검색은 Photon / OpenStreetMap을 사용하며, 후보의 주소를 확인해 선택합니다.

대중교통 조회에는 기존 **`KAKAO_REST_API_KEY`**를 공유하고 카카오디벨로퍼스의 해당 앱에서 **카카오맵 사용 설정 ON**이 필요합니다. 새 키 이름이나 별도 대중교통 키는 필요하지 않습니다. API는 여행 날짜·출발시각 옵션을 받지 않으므로 미래 일정의 배차·실시간 지연을 예측하는 값으로 표시하지 않습니다. 카카오맵의 [응답 저장 정책](https://devtalk.kakao.com/t/api-api/151980)에 따라 서버·브라우저 응답 캐시와 일정의 자동 저장에 결과를 사용하지 않습니다. 펼칠 때마다 조회하고 닫으면 결과를 지웁니다. 열린 조회에서 선택한 경로의 시간은 해당 구간과 뒤 일정의 타임라인에만 미리 보여줍니다. 예를 들어 09:00 도착역에서 53분 경로를 선택하면 첫 관광지는 09:53으로 표시합니다. 조회 닫기·재조회·화면 이동·일정 편집 때 미리보기를 해제하며, 저장·편집 이력·인쇄에는 원래 수동 입력값만 사용합니다. **일정 시간 수정**은 조회한 값을 복사하지 않고 기존 수동 편집창을 엽니다.

차량을 선택하고 출발 장소를 정하면 **차량 예상 이동시간**에서 출발지→첫 관광지의 자동차 예상시간과 이동거리를 조회할 수 있습니다. 자가용·렌터카·택시는 차량 하나로 통합하며, 이전에 저장한 세 수단도 같은 차량 선택으로 복원합니다. 화면에는 예상시간·이동거리와 **일정에 적용** 버튼을 간략하게 표시합니다. 조회만으로 일정을 바꾸지 않으며 적용할 때 소요시간을 분 단위로 올림해 저장하고 뒤 일정을 조정합니다. 이후 시간·메모는 기존 수정 기능으로 바꿀 수 있습니다.

도착역·터미널에서 첫 관광지까지, 그리고 관광지 사이의 이동은 각 구간에서 **도보·시내·마을버스·지하철·차량**을 따로 고릅니다. 출발지에서 선택한 수단을 그대로 적용하지 않으며, 선택은 구간별로 저장·복원합니다. 두 관광지의 직선거리가800m 이내면 도보 추천을, 그보다 멀면 대중교통·차량 고려를 표시합니다. 추천은 실제 보행 경로나 버스·지하철 노선 조회 결과가 아니므로 지도로 실제 경로를 확인해야 합니다. 차량·시내버스·지하철을 고른 구간에는 예상시간 조회가 표시됩니다. 도보 시간과 저장할 대중교통 시간은 기존 일정 수정으로 입력합니다.

자동차 경로시간은 **조회 시점의 현재 교통 기준**으로 미래 여행일의 예측이 아닙니다. 대기·주차·휴게시간은 포함 여부를 확인해 직접 더해 주세요. 조회는 명시적 펼침·버튼에서만 요청하고 같은 좌표 쌍을5분 캐시합니다. 경로가 없거나 차량으로 이동할 수 없는 지점이면 안내를 표시하며 직선거리로 소요시간을 만들어 대체하지 않습니다. 로컬 `.env`와 Cloudflare Secret에 별도 **`KAKAO_REST_API_KEY`**를 설정합니다. 브라우저와 ZIP에는 실제 키를 포함하지 않습니다.

관광지를 교체하면 그 장소와 연결된 이전 이동시간을 초기화합니다. 해당 구간의 이동수단을 바꿨을 때도 시간을 다시 정하며, 차량 종류만 바꿀 때는 같은 경로의 시간을 유지합니다. 내부 이동수단은 출발 교통편과 별개입니다. 관련 없는 구간·메모·출발시각과 지역 간 교통편은 유지합니다.

지역 간 교통편은 ‘출발지 → 도착역·터미널·공항·항구’와 ‘도착지 → 첫 관광지’를 나눕니다. 시간표를 선택해도 첫 관광지까지 이동시간은 별도로 입력합니다. 직접 입력으로 전환할 수 있으며, 출발 구간의 수동 이동시간은 최대 **72시간**까지 입력할 수 있습니다. 시간·분 입력값을 더해 예상 시각을 계산하며, 수동 입력인 경우 대기·환승도 직접 포함합니다. 필요한 이동시간이 0분인 상태는 미정으로 표시합니다.

출발 시각이나 해당 이동시간을 직접 바꾸면 선택한 시간표 연결을 해제합니다. 출발지·도착지·이동수단을 바꾸면 관련 교통편과 구간 시간을 다시 정합니다. 방문 권역만 바꾸면 선택한 지역 간 교통편은 유지하고 새 첫 관광지까지의 이동시간을 초기화합니다.

## 식사 시간의 주변 맛집

식사 카드의 **식당 직접 입력**에서 추천 목록을 조회하지 않고 식당 이름(1~60자)과 주소·메모(최대 500자)를 저장할 수 있습니다. 다시 열어 수정하거나 **식당 정보 지우기**로 이름과 메모를 비울 수 있으며 식사 소요시간은 유지합니다. 직접 추가한 식사 카드에서도 사용할 수 있습니다. 입력한 내용은 브라우저 임시 저장과 계정 저장·불러오기에 함께 반영됩니다. 입력만으로 식당 위치·영업시간을 조회하거나 오가는 이동시간을 더하지 않습니다.

식사 항목의 ‘지역 맛집 보기’를 펼치면 **한국관광공사 TourAPI의 음식점 정보(contentTypeId=39)**를 조회합니다. 음식 종류를 고르는 단계 없이 해당 지역의 음식점을 함께 보여줍니다. 식사 직전 관광지 주소의 시·군·구를 확인해 같은 행정구역의 음식점으로 좁힙니다. 예를 들어 대전 유성구 일정에는 동구 식당을 섞지 않습니다. 시·군·구가 없는 주소는 시도 범위임을 표시합니다.

**식사 일정에 담기**를 누르면 해당 식사 제목에 식당 이름을, 메모에 주소를 담아 저장합니다. 기존 개인 메모는 보존하며 길이 제한을 넘으면 변경을 적용하지 않고 안내합니다. 식당 위치까지의 이동시간은 자동으로 더하지 않으므로 필요한 이동 항목을 직접 추가합니다.

TourAPI 주소가 `전남광주통합특별시`로 제공되는 광주·전남은 원본 지역코드와 시·군·구 코드·주소를 함께 대조합니다. 같은 주소 접두사 때문에 식당이 누락되거나 광주와 전남이 섞이지 않도록 처리했습니다. 17개 시·도 실제 음식점 조회를 확인했으며, 광주 원본73곳 중 남구10·동구12·북구11·서구21·광산구19곳을 구별 조회했습니다.

운영 서버는 지역코드별로 최대 100건씩 3페이지를 조회하고, 요청한 시·군·구를 주소의 행정구역 토큰으로 대조합니다. 기준 좌표가 있으면 이 후보 안에서 제공 좌표 사이의 직선거리로 정렬해 최대 50곳을 반환합니다. 화면은 처음 5곳을 표시하고 ‘더 보기’로 10곳씩 추가합니다. 좌표가 없는 곳은 거리 계산에서 제외합니다. 직선거리는 도보·차량의 실제 경로나 소요시간이 아닙니다.

TourAPI에 등록된 음식점을 제공하며 전국 모든 음식점이 포함되거나 맛·평점이 보증된 목록은 아닙니다. 음식점 이름·주소·제공 좌표 등을 사용합니다. 방문 전 운영 여부와 위치를 확인해야 합니다. 이전 문화정보원 API는 문화·체육·관광시설 주변 자료로 범위가 좁아 기본 조회에서 제외했으며, 기존 `.env`의 문화 API 키는 변경하지 않았습니다.

첫 조회는 제공기관의 응답에 따라 시간이 걸릴 수 있습니다. 10초가 지나면 대기 안내를 표시하며, 화면은 최대 70초까지 응답을 기다립니다. 같은 지역의 결과는 1시간 캐시합니다.

## 저장과 데이터 출처

일정·편집 내용·날짜별 출발 시각·출발/도착지·선택한 교통편은 계정별 브라우저 임시 저장소에 저장합니다. 다른 기기에서 이어 보려면 **계획표 저장**으로 계정 DB에 보관하고 같은 계정으로 불러옵니다. 저장된 관광 일정은 TourAPI 정보를 다시 불러와 장소 ID를 확인한 뒤 복원합니다. 조회 실패나 삭제된 장소로 복원할 수 없으면 오류를 표시하고 저장본을 보존합니다. 로그인 전 저장 안내는 제목과 여행 조건 사이의 작은 공지로 표시합니다.

데이터 제공기관, 공식 API 링크와 저작권 표시는 화면 맨 아래의 **[데이터 출처 안내](sources.html)** 페이지에 모았습니다. TourAPI 관광·음식점 정보, TAGO 5개 서비스, 카카오모빌리티 자동차 경로, 카카오맵 대중교통 경로와 Photon / OpenStreetMap을 안내하며 **© OpenStreetMap contributors**, **Photon by komoot**를 표시합니다.

체류·수동 이동시간은 예상값입니다. 관광지의 운영시간·휴무·예약·요금·날씨는 일정 생성 조건에 반영하지 않습니다. 교통편의 실제 운행과 관광지·음식점의 운영 여부는 방문 전에 확인해야 합니다.

## API와 서버

브라우저는 같은 서버의 API만 호출하고 인증키는 서버에서 읽습니다.

- `/api/tour/areas`, `/api/tour/places`: 여행지 목록과 관광정보. 지역별 1시간 캐시, 관광 유형별 최대 3페이지 조회.
- `/api/transport/stops`, `/api/transport/trips`: 공식 교통기관 목록과 출도착 운행 시간표. 기관 목록은 24시간, 시간표는 5분 캐시.
- `/api/departures/search`: Photon 장소·주소 검색. 검색 버튼이나 Enter를 누를 때만 요청하며 초당 1회로 제한하고 같은 검색어는 1시간 캐시.
- `/api/restaurants`: TourAPI 지역별 음식점 전체 조회. 지역별 1시간 캐시, 기준 좌표가 있으면 직선거리 정렬.
- `/api/car-route?originLatitude=출발위도&originLongitude=출발경도&destinationLatitude=도착위도&destinationLongitude=도착경도`: 카카오 자동차 추천 경로 요약. 현재 교통 기준 예상시간·거리,5분 캐시, 키는 서버 인증 헤더에서만 사용.
- `/api/transit-routes?originLatitude=출발위도&originLongitude=출발경도&destinationLatitude=도착위도&destinationLongitude=도착경도&mode=local-bus`: 카카오맵 대중교통 경로 요약. `local-bus` 또는 `subway`, 시간·거리·환승·노선 안내. 응답 캐시 없이 매 요청 조회하며 인증키는 서버 헤더에만 사용.
- `/api/auth/session`, `/api/auth/signup`, `/api/auth/login`, `/api/auth/logout`: 아이디·비밀번호 계정과 7일 세션. 모든 응답은 `no-store`이며, 쿠키는 HttpOnly/SameSite, HTTPS에서는 Secure를 사용합니다.
- `/api/plans`, `/api/plans/:id`: 로그인한 계정의 계획 목록·생성·읽기·수정·삭제. 소유자 조건과 수정 버전을 검사하고, 변경 요청은 같은 출처의 JSON 요청만 받습니다. 계산된 화면·관광지 전체 객체·카카오 대중교통 조회 원본은 DB에 저장하지 않습니다.

결과가 조회 한도에서 잘리면 응답의 `truncated`로 표시합니다. 외부 API 실패를 임의의 데이터로 대체하지 않습니다. Photon 공개 데모는 과제용 검색에 사용하며 서비스 규모가 커지면 별도 운영 환경이 필요합니다.

정적 파일은 허용 목록으로 제공하므로 `.env`, 서버 소스, ZIP 파일을 웹에서 열 수 없습니다. `.env`는 Git 추적에서 제외합니다. 로컬 서버는 기본적으로 이 컴퓨터의 `127.0.0.1`에서만 실행합니다.

## Cloudflare Pages에 업로드

배포용 ZIP에는 화면 파일과 API 처리를 위한 `_worker.js`가 함께 들어갑니다. `.env`, 서버 원본, 테스트, `node_modules`는 포함하지 않습니다. 별도의 Node 서버 없이 Cloudflare Pages의 Worker에서 같은 API를 처리합니다.

배포 파일을 다시 만들 때만 개발 도구를 설치하고 다음 명령을 실행합니다.

```powershell
npm ci
npm run build:cloudflare
```

1. 상위 작업 폴더의 **`길-Cloudflare-사진-투명.zip`**을 Cloudflare Pages의 ‘프로젝트 자산 업로드’ 칸에 넣습니다. ZIP을 풀거나 프로젝트 전체 폴더를 올릴 필요는 없습니다. **`길-소스-사진-투명.zip`**은 수정 가능한 원본과 테스트의 보관용이며 Pages 업로드용이 아닙니다.
2. 처음 배포해 프로젝트를 만든 뒤 **Settings → Variables and Secrets → Add**에서 `DATA_GO_KR_SERVICE_KEY`를 추가합니다. 값은 로컬 `.env`의 기존 공통 인증키를 사용하고 **Encrypt**를 선택해 저장합니다. 키 이름과 값만 입력하며 `=`는 넣지 않습니다.
3. 같은 ZIP으로 새 배포를 만듭니다. 새로 등록한 Secret은 이후 배포부터 적용되므로, 첫 배포 뒤 키를 추가했다면 다시 배포해야 합니다. 공개 사이트에서 관광지·교통편·음식점 조회를 확인합니다.

차량 예상시간 기능을 사용하려면 같은 환경에 **`KAKAO_REST_API_KEY`**도 Encrypt로 저장합니다. 계정 저장에는 D1 데이터베이스를 만들고 `account-schema.sql`을 실행한 뒤 Pages의 **`DB` 바인딩**으로 연결해야 합니다. **`AUTH_SECRET`**도 Secret으로 등록합니다. 기존 프로젝트도 이번에 DB 설정을 추가해야 하며 설정 저장 후 새 ZIP을 배포합니다. 자세한 순서는 작업 폴더의 `Cloudflare-계정DB-배포안내.txt`를 참고합니다. `.local` DB와 비밀값은 ZIP에 포함하지 않습니다.

ZIP은 이미 빌드된 파일이므로 대시보드의 직접 업로드에는 빌드 명령이나 Node 호환 설정이 필요하지 않습니다. 로컬 Wrangler 설정은2026-10-20을 사용합니다. 키는 사용하는 배포 환경에 등록합니다. 실제 키를 ZIP이나 공개 파일에 넣지 않습니다.

공식 문서: [직접 업로드](https://developers.cloudflare.com/pages/get-started/direct-upload/), [Worker 고급 모드](https://developers.cloudflare.com/pages/functions/advanced-mode/), [Secret 설정](https://developers.cloudflare.com/pages/functions/bindings/#secrets).

로컬 Cloudflare 환경은 ZIP을 만든 뒤 `npx wrangler d1 execute DB --local --file=./account-schema.sql`로 테이블을 준비하고 `npm run dev:cloudflare`로 확인할 수 있습니다. 로컬 인증용 `AUTH_SECRET`은 비공개 `.dev.vars`에 별도로 설정합니다. 실제 배포 시에는 대시보드의 Secret을 사용합니다. Node 서버의 SQLite와 Wrangler의 로컬 D1, 실제 배포 D1은 서로 독립적입니다. 캐시는 Worker 인스턴스별 메모리에 저장되므로 새 인스턴스에서는 다시 조회합니다.

`npm test`로 자동 테스트를 실행하며, 실행 결과의 통과·실패 수를 확인합니다. 외부 API를 대신한 테스트 응답으로 서버와 Cloudflare Worker의 오류 처리·캐시·정적 파일 차단, 관광정보 변환, 시간표 정규화·선택·복원, 음식점 거리 정렬·시군구 범위·빈 목록 형식, 일정 편집·저장과 날짜·시간 선택을 확인합니다. Worker의 HTML 주소 처리와 인증키 비노출, 외부 리디렉션 차단, 카카오 자동차 예상시간의 명시적 일정 적용·키 변경과 장소·수단 변경 시 이전 이동시간 초기화도 확인합니다. 1회 환승의 대기시간·날짜 계산, 모바일 선택창의 화면 경계·키보드 크기 변경·포커스 유지, 한글 조합 검색과 늦은 응답 처리, 이전 차량 유형의 저장 복원도 검증합니다. 대중교통 표시 전용 조회·무캐시·노선 요약과 시작/노트 화면 이동·기존 노트 보존·복원 실패·삭제 처리도 확인합니다. 추천 관광지 제외·복구, 전체 카탈로그에서 관광지 교체·추가, 일정 재배치, 식당 선택의 메모 보존과 v8 저장 복원도 검증합니다. 식당 직접 입력의 길이·제어문자 검증, 메모의 줄바꿈, 삭제 후 식사시간 유지와 저장·복원도 포함합니다.

실제 TourAPI 지역·관광정보 조회와 TAGO 5개 서비스의 기관 목록·운행 시간표 조회를 확인했습니다. TourAPI 부산 음식점 총301건 중 표본3건의 이름·주소·좌표를 확인했습니다. 표시 한도를50곳으로 늘린 실행 서버에서 대전 유성구 음식점41건 모두 유성구 주소임을 확인했고, 화면에서도 분류 선택 없이 시군구 범위가 표시됩니다. 제공 건수와 가능한 운행편은 조회 날짜와 제공기관의 갱신에 따라 달라집니다.

Cloudflare 로컬 workerd에서도 첫 화면·출처 페이지, 실제 지역17곳·서울 관광정보363건·유성구 음식점41건·출발지 검색·열차역 검색을 확인했습니다. 자동차와 대중교통 경로 조회도 실제 키로 확인했고, 대중교통 응답은 `no-store`이며 비공개 소스·`.env` 접근은 차단됩니다. 모바일 콘텐츠 폭320·375·430px와 태블릿768px에서 페이지 가로 넘침이 없고, 실제 일정 편집 저장·조회·시간 적용과 선택창 화면 경계를 확인했습니다. 공개 Cloudflare 주소에서의 동작은 최신 ZIP 업로드와 Secret 등록 후 확인합니다.

- `tago-server.mjs`, `transport-ui.js`: TAGO 기관·시간표 조회와 교통편 선택

- `transit-routing.mjs`, `transit-routing-ui.js`, `transit-routing-ui.css`: 카카오맵 대중교통 경로의 표시 전용 조회

## 여행 사진 디자인 버전

- 경복궁 경회루·부산 광안리·설악산·제주 성산 해안·경주 동궁과 월지·강릉 경포해변·순천만·통영 이순신공원 사진 8장과 관광지명·한 줄 소개를 표시합니다. 선택 여행지와 무관한 국내 풍경이며 사진마다 테마를 바꾸지 않습니다.
- 모든 사진은 Wikimedia Commons 파일 페이지에서 저작자와 CC BY-SA 4.0/3.0 또는 CC0 조건을 확인했습니다. 메타데이터는 `backdrop-photos.js`, 사진별 원자료·라이선스·조정 내용은 하단 출처 안내 옆의 ‘사진 이용 안내’에 표시합니다. 공공누리와 Creative Commons를 혼용하지 않습니다. CC BY-SA 사진의 조정본은 같은 라이선스를 따릅니다.
- 원본 또는 Commons 공식 고해상도 파생본을 폭 2400px·JPEG 품질 85로 웹 전달용 최적화했습니다. 색상·풍경 내용은 변경하지 않았으며 배경은 화면 비율에 맞춰 일부가 잘릴 수 있습니다. 작은 이전 사진과 로고를 피하려던 추가 확대는 교체했습니다. AI 보정 후보는 사용하지 않았습니다.
- 패키지 사진은 관광 API와 독립적으로 불러옵니다. 정확한 로컬 파일명, 저작자·출처·라이선스 URL을 검사합니다. 목록이 없거나 유효하지 않을 때만 기존 TourAPI 배경 API를 조회하며 이 API는 `Type1`만 허용합니다. 관광정보 키는 서버에서 사용하고 새 키는 필요하지 않습니다.
- 첫 화면에서만 15초 간격으로 자동 전환합니다. 전환·멈춤 버튼은 없으며, 백그라운드 탭·동작 줄이기 설정에서는 전환하지 않습니다. 데이터 절약 모드는 이미지와 배경 API 모두 요청하지 않습니다. 사진을 불러오지 못해도 여행 계획 기능은 유지합니다.
- 첫 화면의 카드·입력칸·임시 안내는 흰색 배경 농도 10%, 흰색 글씨와 그림자로 표시합니다. 첫 화면에서 노트로 이동하면 배경 사진을 숨깁니다. 화면 이동 시 이전 화면의 성공·일반 임시 메시지는 즉시 지우며, 같은 화면의 처리 중 표시·오류와 새 화면에서 발생한 안내는 유지합니다.
- 밝거나 복잡한 사진에서도 읽을 수 있도록 첫 화면의 입력 영역에 일정한 반투명 음영을 적용하고 테두리와 글자 그림자를 보강했습니다. 작은 안내는 12px로 표시하며 비활성 입력칸도 과도하게 흐려지지 않게 합니다. 사진 전환 중 생기던 수직 경계를 피하도록 첫 화면의 backdrop-filter는 제거했습니다. 제목 주변 그라데이션·색 띠·밑줄과 사진 소개 박스는 제거하여 풍경이 그대로 보이게 했습니다. 달력·선택 목록은 흰 배경·진한 글씨를 유지하고 노트 색상에는 영향을 주지 않습니다.

## 계획 노트 화면 정리

계획 노트는 사진 없이 맑은 연파랑 바탕·흰색 카드·네이비 글씨로 구성합니다. 크림색과 청록색은 사용하지 않습니다. 저장 버튼 영역을 작게 정렬하고 날짜별 카드와 타임라인의 색감을 통일했습니다. 출발지나 이동시간이 미정인 날짜가 있으면 제목 아래에 한 번만 안내를 표시하며 별도의 제목 라벨은 붙이지 않습니다. 필요한 정보가 채워지면 안내를 숨기고, 미정 이동을 추가하거나 되돌리면 다시 표시합니다. 안내 상태는 현재 일정에서 계산하며 일정에 저장하지 않습니다.

## 추천 동선과 편집 기록

- 새 추천은 같은 권역의 첫 관광지를 기준으로 가까운 다음 관광지를 직선거리로 고릅니다. 좌표가 부족하면 기존 선택 방식으로 돌아갑니다. 인기도 순위나 실제 최단 경로를 계산하는 기능은 아니며, 저장된 선택과 사용자가 정한 순서는 유지합니다.
- 수동 편집은 현재 탭에서 최대 20단계 되돌리기·다시 실행을 지원합니다. 제목·메모·시간·식당 선택·관광지 교체·추가·삭제·순서를 복구하며 다음 일정 시각을 다시 계산합니다. 기록에는 편집 입력만 보관하고 외부 API 조회 원본은 넣지 않습니다. 새 노트·불러오기·새로고침·계정 전환 시 기록을 비우며 계정 DB에는 편집 이력을 저장하지 않습니다.
- 미정 이동시간은 임의 추정값으로 채우지 않습니다. 차량은 확인한 경로의 시간을 명시적으로 적용할 수 있고, 대중교통은 열린 조회의 타임라인 미리보기만 지원하며 자동 저장하지 않습니다. 식당 이름·주소 선택으로 경유 구간을 자동 생성하거나 공개 공유 링크를 만들지 않습니다.

## 두 사람이 함께 작업하는 순서

1. GitHub의 상대방 변경 내용을 확인하고 작업 브랜치에서 수정·검증합니다.
2. 완료한 소스를 커밋하고 푸시합니다. 공동 작업은 소스 저장소를 기준으로 진행합니다.
3. 사용자가 배포 ZIP 생성을 요청하면 상대방 수정까지 반영된 최종 커밋을 확인하고 ZIP을 만듭니다. 배포 파일에는 기준 커밋 번호를 기록합니다.
4. 해당 ZIP으로 배포하고 공개 사이트에서 확인합니다. 커밋·푸시만 요청한 작업에서는 ZIP 생성과 배포를 진행하지 않습니다.
