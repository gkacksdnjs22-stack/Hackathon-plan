# 수정본 배포 안내

## 무엇을 올리나요?

- `길-Cloudflare-사진-투명.zip`: Cloudflare Pages에 직접 올리는 배포 파일입니다. ZIP을 풀거나 소스 ZIP을 배포하지 마세요.
- `길-소스-사진-투명.zip`: 수정한 소스와 테스트의 보관용입니다.
- 배포 ZIP은 화면·검증된 배경 사진·사진 메타데이터와 API Worker를 포함합니다. 실제 키, 로컬 계정 DB, 비밀값은 포함하지 않습니다.

## 기존 Pages 프로젝트 업데이트

1. 기존 `rode-hackathon` Pages 프로젝트를 엽니다. 새 프로젝트를 만들 필요는 없습니다.
2. 실제 사이트에 쓰는 배포 환경의 Settings → Variables and Secrets에서 기존 `DATA_GO_KR_SERVICE_KEY`를 유지합니다. 이 키는 관광지·식당·TAGO 교통편에 쓰입니다. 서비스별 활용신청 승인은 별개입니다.
3. 차량·시내버스·지하철 경로 조회에는 `KAKAO_REST_API_KEY`가 필요합니다. 카카오 개발자 사이트의 해당 앱에서 발급한 REST API 키를 Cloudflare Secret(Encrypt)으로 등록하세요. JavaScript 키가 아닙니다. 대중교통은 카카오맵 사용 설정도 확인하세요. 키를 채팅·GitHub·공개 파일에 붙여 넣지 마세요.
4. 설정 저장 후 새 배포를 만들어 `길-Cloudflare-사진-투명.zip`을 업로드합니다. 새 Secret은 새 배포에 반영되므로 설정만 저장하고 끝내지 마세요. 기존 Secret 값을 지우거나 소스에 입력할 필요는 없습니다.
5. 배포 완료 후 페이지를 새로고침하고 이동 카드에서 지하철·시내버스·차량을 각각 선택해 ‘예상시간’ 조회를 펼쳐 보세요. 오류 문구가 키 없음에서 인증·권한 오류로 바뀐다면 해당 서비스 설정·승인을 별도로 확인해야 합니다. 키 추가만으로 모든 경로 조회 성공이 보장되지는 않습니다.

2026년 10월 21일 초기 점검에서는 공개 사이트 `rode-hackathon.pages.dev`의 차량·시내버스·지하철 조회가 모두 `503 KEY_MISSING`이었으나, 이후 키 설정이 반영되어 공개 사이트와 로컬 서버에서 세 조회 모두 HTTP `200`으로 정상 응답하는 것을 확인했습니다. 초기 키 누락은 해결된 상태이며 정상 동작 중인 기존 Secret은 유지하세요. 로컬 `.env`와 Cloudflare 배포 환경의 Secret은 별개이며, 개발자 콘솔에서 키를 발급·활성화해도 배포 사이트에 자동으로 전달되지 않습니다. 처음 설정하거나 키를 변경할 때는 기존 Pages 프로젝트의 **Production(프로덕션)** 환경에 정확한 이름 **`KAKAO_REST_API_KEY`**로 Secret을 등록하고 저장한 뒤 새 배포를 만들어야 합니다.

## 계정 저장은 선택 사항

직접 여행 계획서를 편집하는 기능과 계정 저장은 별개입니다. 로그인·다른 기기 저장을 쓸 때만 D1 DB, `DB` 바인딩, `account-schema.sql` 적용, `AUTH_SECRET`이 필요합니다. 이미 계정 저장을 사용한다면 기존 DB·Secret을 보존하세요. 이를 새로 만들거나 바꾸는 작업은 이번 ZIP 업로드에 포함되지 않습니다.

## 확인할 항목

- 여행지·관광지 생성, 식당 조회, 기차·버스 시간표 조회
- 식당 직접 입력·수정·정보 지우기와 식사시간 유지, 저장한 노트의 식당명·메모 복원
- 이동시간 미정(0분) 상태의 메모 저장과 실제 시간 입력
- 카카오 경로 오류 시 지도 링크와 수동 편집 유지
- 시작 화면의 사진·관광지명·한 줄 소개, 15초 자동 전환
- 노트 화면에서 사진·소개·사진 출처가 숨겨지고 연파랑·흰색 배경으로 표시되는지, 시작 화면으로 돌아왔을 때 사진이 다시 보이는지
- 이용 안내 링크, 기존 저장 노트 불러오기
- 미정 이동이 남은 일정은 임시 계획입니다. 여객선 등 제공기관 시각이 이상하면 선사·운영기관에 확인하세요. 데이터를 임의로 추정해 고치지 않았습니다.

## 사진 디자인 버전 확인

첫 화면의 사진은 경복궁·광안리·설악산·제주 성산 해안·경주·경포해변·순천만·통영의 8장입니다. 모두 로고·워터마크가 없는 고해상도 공개 사진을 확인했고 폭 2400px로 크기·용량만 최적화했습니다. 사진의 풍경 내용은 바꾸지 않았습니다. 사진마다 이름과 짧은 소개를 15초마다 자동 전환하며 전환·멈춤 버튼은 없습니다. 첫 화면의 카드·입력칸·상단 임시 안내는 흰색 배경 농도 10%와 흰 글씨로 표시합니다.

사진별 작품명·저작자·Creative Commons 라이선스·원본 링크와 크기 조정 내역은 하단 ‘사진 이용 안내’에 있습니다. CC BY-SA 사진의 조정본은 같은 라이선스로 제공합니다. 정적 사진 8장과 `backdrop-photos.js`가 배포 ZIP에 포함되어 배경 API의 지연·빈 결과와 관계없이 표시됩니다. 이 사진에는 별도 키가 필요하지 않습니다. 정적 목록이 없거나 유효하지 않을 때만 기존 Type1 관광사진 API를 조회합니다. 백그라운드 탭·동작 줄이기 설정에서는 전환하지 않고 데이터 절약 모드에서는 사진 자체를 요청하지 않습니다.

노트에는 사진이 없고 연파랑·흰색·네이비 색상을 사용합니다. 크림색과 청록색은 사용하지 않습니다. 화면을 이동하면 이전 화면의 성공·일반 임시 메시지는 바로 사라집니다. 같은 화면의 처리 중 표시·오류, 새 화면에서 발생한 안내는 유지합니다.

밝은 사진에서의 가독성을 위해 입력 영역에 일정한 반투명 음영을 적용하고 테두리·글자 그림자를 보강했습니다. 작은 안내는 12px로 표시하며, 사진 전환 중 생기던 수직 경계를 피하도록 첫 화면의 backdrop-filter는 제거했습니다. 제목 주변 그라데이션·색 띠·밑줄과 사진 소개 박스는 제거했습니다. 제목과 소개는 사진 위에 글씨만 표시하고 달력·선택 목록은 흰 배경에 진한 글씨를 유지합니다.

## 식당 직접 입력 추가

식사 카드에서 추천 조회 없이 식당 이름과 주소·메모를 입력할 수 있습니다. 기존 추천 기능과 저장 방식은 유지합니다. 입력한 내용을 다시 수정하거나 지울 수 있고, 식사 시간은 변경하지 않습니다. 이름은 1~60자, 주소·메모는 최대 500자이며 직접 추가한 식사 카드에서도 사용합니다. 이 버전은 이전 디자인·기능 수정 사항을 포함합니다.

소스를 수정한 뒤 `npm test`로 검증하고 `npm run build:cloudflare`로 배포 ZIP을 생성합니다. 실제 키·로컬 DB·로그·검토용 화면 캡처는 배포·소스 보관 ZIP에 포함하지 않습니다.

## 계획 노트 화면 정리

계획 노트는 사진 없이 맑은 연파랑 바탕·흰색 카드·네이비 글씨로 구성합니다. 크림색과 청록색은 사용하지 않습니다. 저장 버튼 영역을 작게 정렬하고 날짜별 카드와 타임라인의 색감을 통일했습니다. 출발지나 이동시간이 미정인 날짜가 있으면 제목 아래에 한 번만 안내를 표시하며 별도의 제목 라벨은 붙이지 않습니다. 필요한 정보가 채워지면 안내를 숨기고, 미정 이동을 추가하거나 되돌리면 다시 표시합니다. 안내 상태는 현재 일정에서 계산하며 일정에 저장하지 않습니다.
