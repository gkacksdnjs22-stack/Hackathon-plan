길 — 계정별 여행 계획 저장 / Cloudflare 업로드 안내

이번 업로드 파일: 길-Cloudflare-사진-투명.zip
이전 ‘교통연동.zip’, ‘업로드.zip’은 이번 수정이 포함되지 않은 파일입니다.

이번에 처음 한 번만 설정할 것

1. Cloudflare 대시보드 → Storage & Databases → D1 SQL Database → Create Database
   DB 이름: gil-plans
   이 DB는 로컬 DB와 별개입니다. 로컬에서 만든 테스트 계정·계획은 올라가지 않습니다.

2. 만든 gil-plans → Console
   같은 작업 폴더의 ‘길-계정DB-초기설정.sql’을 메모장으로 열어 전체 내용을 복사합니다.
   Console에 붙여넣고 Execute를 누릅니다. SQL 파일을 사이트 ZIP 업로드 칸에 넣지 않습니다.
   기존 테이블을 지우는 명령은 없으며, gil_users/gil_sessions/gil_rate_limits/gil_plans를 만듭니다.

3. Workers & Pages → rode-hackathon → Settings → Bindings → Add
   유형: D1 database
   Variable name: DB (대문자 두 글자)
   Database: gil-plans
   Production 환경에 연결하고 저장합니다. Preview도 사용할 경우 별도로 연결합니다.

4. 같은 프로젝트 → Variables and Secrets → Add
   유형: Secret / Encrypt
   이름: AUTH_SECRET
   값: 여행의-결\.local\AUTH_SECRET.txt 파일의 내용 한 줄
   이름과 값만 입력하며 = 기호나 따옴표는 넣지 않습니다.
   이 비밀값은 비밀번호 보호에 사용됩니다. 안전하게 보관하고 함부로 바꾸지 마세요.
   기존 계정이 있는 상태에서 변경·분실하면 기존 비밀번호로 로그인할 수 없습니다.
   비밀 파일과 DB 파일은 사이트 업로드·제출·공유 대상이 아닙니다.

   기존 DATA_GO_KR_SERVICE_KEY, KAKAO_REST_API_KEY 설정은 유지합니다.
   두 API 키도 가능한 Secret 유형으로 보관합니다.

5. 배포 생성 → Production → ‘길-Cloudflare-사진-투명.zip’ 업로드 → 저장 및 배포
   프로젝트 전체 폴더, .env, .local, SQL 파일을 업로드하지 않습니다.
   Secret과 DB 연결은 설정을 저장한 뒤 만든 새 배포부터 적용됩니다.
   ZIP은 이미 빌드돼 있어 별도 빌드 명령이나 Node 호환 옵션은 필요하지 않습니다.

배포 후 확인

- 로그인 · 회원가입에서 아이디(영문·숫자·밑줄 3~24자), 비밀번호(10~128자)로 가입합니다.
- 여행 노트를 만든 뒤 ‘계획표 저장’에서 이름을 붙여 저장합니다.
- 다른 브라우저나 휴대폰에서 같은 계정으로 로그인 → ‘저장한 계획’ → 불러오기를 확인합니다.
- 다른 계정으로 로그인하면 이전 계정의 목록·작성 중인 노트가 보이지 않아야 합니다.
- 관광지·식당 목록과 교통편 조회도 함께 확인합니다.

여행 노트는 자동으로 계정 DB에 업로드하지 않습니다. 편집 중에는 계정별 브라우저 임시 저장을 사용하고,
‘변경사항 저장’을 누르면 계정 DB를 갱신합니다. 다른 기기와 수정이 겹치면 덮어쓰기 대신 선택을 안내합니다.
계정당 최대100개, 계획당 최대256KiB입니다. 이메일 인증·계정 복구·비밀번호 재설정은 이번 범위에 포함하지 않습니다.
관광정보가 API에서 삭제된 경우 복원이 실패할 수 있으며, 이때 저장한 계획은 삭제하지 않습니다.

로컬 실행과 재빌드

Node.js 24 이상. 여행의-결 폴더에서 npm start를 실행하면 로컬 SQLite DB와 비밀값을 자동 준비합니다.
로컬 DB: 여행의-결\.local\gil.sqlite
로컬 서버와 실제 Cloudflare D1은 서로 독립적입니다.
수정 후 ZIP을 다시 만들 때: npm ci → npm run build:cloudflare

개발용 인증 구성

비밀번호 원문은 저장하지 않습니다. 무작위 salt와 PBKDF2-SHA256 100,000회 후 별도 AUTH_SECRET을
사용한 HMAC을 저장합니다. Cloudflare WebCrypto의 반복수 제한에 맞춘 교육용 구현이며,
OWASP 권고 600,000회와 동등한 것으로 설명하지 않습니다. 서비스 확장 시 관리형 인증으로 이전하는 편이 좋습니다.
세션은 HttpOnly/SameSite 쿠키(HTTPS에서는 Secure)로, DB에는 세션 토큰의 해시만 보관합니다.
